
# 🍼 BabyCash – Aplicación del Personal Software Process (PSP)

## 📌 **Descripción del Proyecto**

**BabyCash** es una herramienta web diseñada para optimizar la gestión de ventas, inventario y reportes del negocio *Pañalera y Variedades Soffys*. Permite organizar transacciones, controlar el stock, generar reportes y realizar operaciones de manera clara y eficiente.

Este repositorio incluye la aplicación del **Personal Software Process (PSP)** durante el desarrollo del proyecto con el fin de mejorar la calidad del código, reducir defectos y optimizar la estimación del esfuerzo.

---

# 🧠 **Objetivo del PSP en BabyCash**

Aplicar prácticas personales de ingeniería de software para:

* Mejorar la **precisión de estimaciones** (tiempo, tamaño y esfuerzo).
* Reducir defectos durante las fases tempranas del desarrollo.
* Aumentar la **calidad del producto** mediante revisiones sistemáticas.
* Obtener métricas reales sobre productividad personal y del equipo.
* Establecer un proceso repetible, medible y mejorable en cada sprint.

---

# 🛠️ **Herramientas Utilizadas en el PSP**

## ⏱️ **1. Time Tracking (Registro de Tiempo)**

Herramientas utilizadas para medir esfuerzo real:

* **Jira Tempo**

Se emplearon para registrar:

* Horas de análisis
* Horas de diseño
* Horas de codificación
* Revisiones
* Pruebas
* Postmortem

---

## 🐞 **2. Defect Tracking (Seguimiento de Defectos)**

Herramientas usadas para registrar, clasificar y resolver defectos:

* **GitHub**
* **Jira**

Se registró información como:

* Tipo de defecto
* Fase donde se generó
* Fase donde se detectó
* Tiempo invertido en corregir
* Archivos afectados

---

## 📊 **3. Estadísticas y Análisis**

Para el análisis de datos del PSP se utilizaron:

* **Excel**
* **Google Sheets**

Métricas estudiadas:

* LOC por módulo
* Productividad (LOC/hora)
* Densidad de defectos
* Tiempo por fase
* Desviación entre estimado y real

---

# 🔄 **Flujo de Trabajo PSP en BabyCash**

El equipo aplicó un ciclo PSP por cada módulo del sistema (**Autenticación, Ventas, Inventario, Reportes, Pagos y Carrito**).

### **1. Planificación**

* Estimación de tamaño (LOC estimadas)
* Esfuerzo aproximado por módulo
* Registro inicial en Excel PSP

### **2. Diseño**

* Diagramas de flujo
* Bocetos UI
* Diseño de APIs (cuando aplicaba)

### **3. Codificación**

* Implementación siguiendo estándares del proyecto
* Control de versiones en GitHub
* Commits diarios por módulo

### **4. Revisiones**

* Revisión personal del código
* Revisión cruzada entre integrantes
* Análisis de errores tempranos

### **5. Pruebas**

* Pruebas manuales del frontend
* Pruebas API con Postman
* Validación funcional de requisitos

### **6. Postmortem**

* Comparación entre esfuerzo estimado y real
* Número de defectos por fase
* Ajustes al proceso personal
* Lecciones aprendidas
